# 教学与客户安排（背景记忆）

> 本项目是付费教学项目：两位教师带一名学生客户完成整个系统。

## 人员

- **用户（本仓库主人）**：技术教师，负责硬件/固件/Unity/Python 全部技术教学；中英混用，要求文档简体中文
- **Nick**：心理学背景教师，负责 4h 线下心理学课（主题开放）+ 实验督导；建议方向：N1 心理生理学基础（在 L7 状态模型课之前）、N2 实测调参场（需游戏原型 + 实验 SOP 完成后）
- **学生客户**：一名（她），项目想法讨论中逐步定型

## 课时结构（共 22h）

| 板块 | 时数 | 形式 |
|---|---|---|
| L0 导论 | 1h | 线上（原定 2026-09 第一周，日期由客户定） |
| L1 硬件课 | 2h | **线下宁波 2026-09-11（周五）**：组装、调试、连 PC；硬件之后留在学员处 |
| L2–L8 技术课 | 14h（7×2h） | 线上，约每周 2 堂（周三晚+周六），架构→固件→数据通路→Unity×2→状态模型→难度/分析 |
| E1 实验设计 | 1h | 线上（建议邀 Nick 共同出席） |
| N1–N2 Nick | 4h | 线下宁波，日期 Nick 与学员直约 |

- 用户 2026-09-06 至 09-15 在宁波；9/6–9/10 为自己的硬件备课实验期（不计课时）
- 国庆 10/1–10/8 默认停课
- 课外数据采集 4–6h：6–10 位受试者 × 3 场（adaptive/fixed/sham）+ 主观量表
- 排程详情见 SCHEDULE.md；客户版为简体中文 Word/PDF（`课程排程_SCHEDULE.docx/.pdf`，用本机 Word COM 从 HTML 转换生成）

## 交付物约定

- 给客户看的文件：简体中文、Word/PDF 格式（本机有 MS Word，可 COM 自动化转换）
- 文档中教师名用 [You] 占位，发出前需替换
- SCHEDULE.md 源文件仍是繁体且含旧硬件描述（低优先级待更新）

## 教学设计要点

- 每个 Phase 有可展示成果和 🔑 验收关卡，防止最后才发现整合不起来
- `MockBioTransport` / `fake_device.py` 让无硬件时也能继续 Unity 开发（多人协作/硬件故障保险）
- 排序依赖：N1 → L7（心理学理论先于状态模型课）；L8 + E1 → N2（有原型和 SOP 才能实测）
- vibe coding 是课程卖点之一：教学生如何与 AI 协作写代码（描述需求/验收产出/debug）
