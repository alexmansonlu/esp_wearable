# 教学与客户安排（背景记忆）

> 本项目是付费教学项目：两位教师带一名学生客户完成整个系统。

## 人员

- **用户（本仓库主人）**：技术教师，负责硬件/固件/Unity/Python 全部技术教学；中英混用，要求文档简体中文
- **Nick**：心理学背景教师，负责 4h 线下心理学课（主题开放）+ 实验督导；建议方向：N1 心理生理学基础（在 L7 状态模型课之前）、N2 实测调参场（需游戏原型 + 实验 SOP 完成后）
- **学生客户**：一名（她），项目想法讨论中逐步定型；**零编程基础**，全程 vibe coding 教学法（2026-09 确定）：AI 写代码 + 每课后技术教师人工 code review 口头答辩 + git commit 为作业交付单位；需同时学 git。学生手册见 lessons/vibe_coding_入门.md

## 项目五阶段框架（用户 2026-09 提出，作为研究叙事主线）

S1 目标定义 → S2 硬件与数据管线（含校准与数据集管线）→ S3 严谨实验（生理数据→情绪状态的映射）→ S4 模型设计与验证（鲁棒/公平/跨人）→ S5 游戏整合。
注意：这是**逻辑顺序**，实际排期为双轨并行（研究轨 S1–S4 与游戏构建轨并行，S5 汇合）；游戏先用规则式状态判断占位，S4 模型好了再替换。
用户额外想法：① 正面情绪/兴奋给奖励机制（形态待 L0 定，见 lessons/L0_导论课.md D2）；② 可能用笔记本前置摄像头做表情/情绪识别（建议定位为 S3 可选增强通道，只存特征不存视频，隐私条款单列，游戏 v1 实时控制不依赖）；③ 模型探索提及 transformer/ANN/RNN/LSTM——已用"模型复杂度阶梯"框定预期：第 1 级经典 ML 为主力交付，LSTM 为对比实验，Transformer 只做展望（数据量不支持训练）。

## 教学设计要点

- 每个 Phase 有可展示成果和 🔑 验收关卡，防止最后才发现整合不起来
- `MockBioTransport` / `fake_device.py` 让无硬件时也能继续 Unity 开发（多人协作/硬件故障保险）
- 排序依赖：N1 → L7（心理学理论先于状态模型课）；L8 + E1 → N2（有原型和 SOP 才能实测）
- vibe coding 是课程卖点之一：教学生如何与 AI 协作写代码（描述需求/验收产出/debug）

## 游戏设计方法论（用户 2026-09-03 定）

- **先简单、先 demo、不上完整机制**：游戏按 demo 阶梯推进 A 节拍器点击 → B 单轨下落 → C 4 轨+谱面 → D 假情绪旋钮（键盘模拟状态、只动一个杠杆）→ E 接真传感器。A–D 不需要硬件。Demo A（时间判定 + 即时反馈）是最重要的最小机制
- L0 §5 的 G1–G5（参考游戏、最小机制、按键数 1/2/4、情绪→难度杠杆与几档/频率/可见性、正面情绪奖励 + 失误时的温柔反馈）**只讨论不定案**，学生课后与 AI 逐题讨论、带一页提案到 L1；L1 按 lessons/L1_硬件课.md 反馈，每题结论分"当场定 / demo 验证 / 继续想"
- 用户对杠杆的倾向（仅供参考，最终由学生定）：密度（tier）三档、小节边界、先无感；BPM 变速不建议首选（变调 + 实验不可比）；放宽判定窗口会改变 accuracy 含义，需记录
- L1 验收哲学：评"她怎么用 AI"（L0 复制粘贴 / L1 能复述 / L2 能解释为什么 / L3 能质疑 AI 或主动拆小），不评记忆；第一次作业以鼓励为主，方案过于复杂时改问"拆成几个 demo"
- S2–S5 决策清单已从 L0 移出到 lessons/S2-S5_决策清单.md（2026-09-03）：每项标 🔒教师定 / 🤝先与 Nick 对齐 / 🗣️与学生讨论 / 📣告知学生；不发学生。需与 Nick 先对齐的：校准段设计、受试者数据管理、ground truth 方案、sham 设计、受试者与同意书、SOP、严谨定义、生理 HUD 观察者效应——建议 L3（9/19）前对一次，E1 前再对一次
- 上手分两步（2026-09-03 定）：L0→L1 作业纯 AI 学习（硬件笔记 + 游戏提案，发文件，不用 git）；L1 线下开箱 vibe coding（clone 仓库、只靠 md 文档 + AI 自学仓库、跑 serial_logger、第一次 commit），L1 作业为第一个小测试脚本，L2 开头首次代码答辩。L0 的附录 A/B 已删除，D1–D5 结论记会议纪要
- L1 结构（2026-09-10 改版，用户定）：0:00–0:20 游戏提案**完整定案** G1–G5 + Demo A–E 开发时程现场填表（L2 9/17、L3 9/19，之后每周两堂）→ 休息 10 → 0:30 vibe coding 自行探索 10 分钟 → 硬件走读 40 分钟，她开着 WIRING.md 当参照自己接线（固件教师预烧，PlatformIO 改作业）→ 10 分钟：sensor_check 自检 → 讲 calibrate 做什么 → live_dashboard → record.py 采一场 → 休息 10 → 20 分钟收尾：下次课 Unity（课前装好）+ 作业 = 玩情绪起伏大的游戏采数据、打标签（难度/BPM/分数/失误/漏拍/主观紧张）、让 AI 找相关性（experiment/analysis/prompts.md）。旧版的 T3 数据样例、结构图、烧录环节删除
