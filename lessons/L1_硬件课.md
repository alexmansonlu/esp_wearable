### 4.0 先讲两个共同概念（3 分钟，在 4.1 里一起讲）

**ADC（模数转换）**：传感器给出 0–3.3 V 的连续电压，ESP32 把它量化成 0–4095 的整数（12 位）。`setup()` 里的 `analogReadResolution(12)` 与 `analogSetPinAttenuation(..., ADC_11db)`（[main.cpp:130-133](../firmware/src/main.cpp#L130-L133)）就是配这件事。三路模拟传感器全接 **ADC1**（GPIO32–39），因为 ADC2 在 Wi-Fi 开启时不可用。

**I2C（数字总线）**：两根线（SDA 数据、SCL 时钟）挂多个芯片，每个芯片有地址。本项目：MPU6050 @0x68、MAX30100 @0x57（[main.cpp:137-138](../firmware/src/main.cpp#L137-L138)）。

**固件的节拍**：`loop()` 不用 `delay()`，用 `millis()` 时间戳让几个任务各按各的频率跑——200 Hz 波形、50 Hz GSR、25 Hz 加速度、10 Hz 发包（[config.h:27-31](../firmware/include/config.h#L27-L31)，[main.cpp:174-245](../firmware/src/main.cpp#L174-L245)）。

### 4.2 思知瑞 GSR 皮肤电（9 分钟）

| | 内容 |
|---|---|
| 她先讲 | 它测的是什么？数值上升代表人怎么了？ |
| 机制 | 紧张 → 交感神经 → 手指汗腺分泌微量汗液 → 汗液含电解质 → 皮肤导电性上升。汗腺只受交感神经支配，所以是最"干净"的唤醒度指标，刺激后 1–3 秒可见 |
| 信号怎么到 ESP32 | 两个指套电极之间的皮肤是一个电阻；模块用分压电路把电阻变成电压（内部 2 倍放大 + 0.5–5 Hz 带通），从 `ADC` 引脚（旧批次丝印 `OUT`）输出 → GPIO34（ADC1_CH6）。**必须 3.3 V 供电**：5 V 时输出可能超过 ADC 上限。板上没有电位器 |
| 固件读取 | 50 Hz 任务里连读 8 次取平均（过采样降噪）→ `g_gsrRaw`（[main.cpp:200-211](../firmware/src/main.cpp#L200-L211)） |
| 预处理 | ① 50 点滑动平均 = 1 秒平滑（[main.cpp:33](../firmware/src/main.cpp#L33)）；② 每秒存一点、15 点线性回归斜率 `gsr_slope`（[main.cpp:91-102](../firmware/src/main.cpp#L91-L102)）；③ 校准基线后输出 `gsr_delta = (当前 − 基线) / 基线`（[main.cpp:259-260](../firmware/src/main.cpp#L259-L260)，§5 细讲）；④ quality bit1：读值在 5–4090 之间才算在量程内 |
| 用处 | `gsr_delta` 是五条状态规则每一条都用的量；`gsr_slope` 抓"正在紧张起来"。一切用相对基线的变化量，绝不用绝对值 |
| 她接线 | WIRING §3.2：VCC→3V3，GND→GND，ADC→GPIO34；指套线插到底，套非按键手的食指与中指。Plotter 看 `gsr`：心算 37×23 → 爬升；深呼吸 → 回落 |
| AI 提示词（课后） | 「在 firmware/src/main.cpp 里，从 analogRead(PIN_GSR) 开始，把 GSR 数值一路到写进 JSON 的每一步按顺序讲给我，每步为什么要做。」 |

### 4.3 PulseSensor 光电脉搏（9 分钟）

| | 内容 |
|---|---|
| 她先讲 | 它是光电还是心电？原理一句话 |
| 机制 | PPG：绿光 LED 照进指尖，心脏每跳一次指尖血容量脉动一次，血液吸收绿光，反射光强随脉搏起伏，光敏元件把光强变成电压 |
| 信号怎么到 ESP32 | 连续模拟波形 0–3.3 V → GPIO35（ADC1_CH7）。力度关键：太紧压闭血管没波形，太松漏光噪声大 |
| 固件读取 | 200 Hz 快任务 `analogRead(PIN_PULSE)`（[main.cpp:185-191](../firmware/src/main.cpp#L185-L191)） |
| 预处理：BeatDetector | 从波浪线到心率数字（[BeatDetector.h](../firmware/src/BeatDetector.h)）：① 慢基线扣除；② 峰值包络自适应阈值（包络慢慢衰减、被新峰顶起，阈值取一半，不低于 `minThreshold` 25）；③ 上穿触发 + 不应期 300 ms + 滞回 0.7；④ 逐跳间隔 IBI，只收 300–1500 ms；⑤ `bpm()` = 60000 / 最近 8 个 IBI 平均；⑥ `rmssd()` = 相邻 IBI 差的均方根 = HRV；⑦ 3 秒没心跳当信号丢失 |
| 用处 | `hr_p` 是游玩时统一心率 `hr` 的实际来源（ECG 那时受肌电干扰）→ `hr_delta`；`rmssd_p` 是第二证据：压力上升 → RMSSD 下降 |
| 她接线 | WIRING §3.3：+→3V3，−→GND，S→GPIO35；指尖魔术贴固定、遮光，非按键手。Plotter 一跳一峰；Monitor 看 `{"type":"beat","src":"ppg",...}`；用力压 → 波形变平 → 3 秒后 `hr_p` 变 −1 |
| AI 提示词（课后） | 「逐段讲解 firmware/src/BeatDetector.h 的 update()，假设我没有编程基础，用"抓浪峰"的比喻。然后告诉我 300、1500、0.5、0.7 各是什么意思。」 |

### 4.4 AD8232 心电（8 分钟）

| | 内容 |
|---|---|
| 她先讲 | 三个电极贴哪里？`lead_off` 是什么意思？ |
| 机制 | 心脏每次收缩由一次电去极化波驱动，传到体表约 1 mV。AD8232 放大约 1100 倍并带通滤波，输出 0–3.3 V 心电波形；R 峰极尖锐，逐跳间隔可精确到毫秒——HRV 的金标准 |
| 信号怎么到 ESP32 | OUTPUT → GPIO32（ADC1_CH4）；LO+ → GPIO27、LO− → GPIO14（数字，电极掉了输出高电平） |
| 固件 | 同一个 200 Hz 任务；先查 `ecgLeadOff()`（[main.cpp:60-66](../firmware/src/main.cpp#L60-L66)），没脱落才喂给 `g_ecgBeat`；同一个 BeatDetector 类，`minThreshold` 提高到 40 抗噪——同一段代码同时服务 PPG 与 ECG。**统一心率** `bestHr()` 按 ECG > PPG > MAX30100 取第一个可信的（[main.cpp:68-89](../firmware/src/main.cpp#L68-L89)） |
| 用处 | `hr_e` 是 `hr` 的最高优先来源（静息段最准）；`rmssd_e` 是 HRV 真值；`lead_off` 让坏数据自动被标记 |
| 她接线 | WIRING §3.4：3.3V→3V3，GND→GND，OUTPUT→GPIO32，LO+→GPIO27，LO−→GPIO14，SDN 悬空；酒精棉片清洁后贴三片（红右胸 / 绿左胸 / 橙右下腹，R 峰向下就对调红绿）。`lead_off` 变 0、出现 `src:"ecg"` 的 beat；拔一片 → `lead_off` 变 1，`hr` 自动切到 PPG |
| AI 提示词（课后） | 「firmware/src/main.cpp 的 bestHr() 在做什么？如果 ECG 电极掉了、PulseSensor 也没贴好，hr 会是多少？quality 的 bit0 会怎样？」 |

### 4.5 MPU6050 六轴（7 分钟）

| | 内容 |
|---|---|
| 她先讲 | 它不测情绪，为什么很重要？ |
| 机制 | MEMS：芯片里微米级的硅质量块挂在弹簧上，加速时位移改变电容。静止时也测得到重力 1 g |
| 信号怎么到 ESP32 | 数字：I2C 0x68，加速度在寄存器 0x3B 起 6 字节，±2 g 量程下 16384 = 1 g |
| 固件 | [Mpu6050.h](../firmware/src/sensors/Mpu6050.h)：`begin()` 写 0x6B=0 **唤醒**（上电默认睡眠）、0x1C=0 设 ±2 g、0x1A=3 开 44 Hz 低通；`readMotion()` 算合加速度、减去 1 g 重力取绝对值。主循环 25 Hz 读、5 点滑动平均 |
| 用处 | `acc` 是运动门控：`acc > 0.8g` 时状态判断冻结。PPG、GSR、ECG 全都怕动作伪影，它是防线 |
| 她接线 | WIRING §3.5：VCC→3V3，GND→GND，SDA→GPIO21，SCL→GPIO22；戴在 PulseSensor 同一侧手背。静置 `acc` ≈ 0；甩手 → 飙升，同时看 PulseSensor 波形被打乱 |
| AI 提示词（课后） | 「firmware/src/sensors/Mpu6050.h 里 begin() 写了三个寄存器，各是干什么的？如果不写 0x6B 会怎样？readMotion() 最后一行为什么是 mag − 1.0？」 |

### 4.6 裸 MAX30100（2 分钟，只讲不接）

数字式 PPG，I2C 0x57。多数廉价板的 I2C 上拉接 1.8 V 轨，直接用通信失败，要改电阻。`config.h` 里 `ENABLE_MAX30100 0`（[config.h:10](../firmware/include/config.h#L10)），整套代码用 `#if` 包着，关掉不影响其他传感器。`hr_m` 是 `hr` 的最低优先兜底。

### 4.7 一句话收口（对照 WIRING §4 布局总表复查一遍全部接线）

GSR 说"现在多紧张"，心率 / HRV 说"紧张持续了没有"，ECG 保证这些数字有真值可对照，MPU6050 说"这些数据能不能信"，游戏表现说"紧张是专注还是崩溃"。`quality` 三个位：bit0 有可信心率、bit1 GSR 在量程、bit2 基线就绪，全好 = 7。

### 5.1 calibrate 做什么（2 分钟，讲）

- 电脑发一行 `calibrate` → 固件从这一刻起累积 30 秒（[config.h:33](../firmware/include/config.h#L33)）：GSR 平滑值每 50 Hz 加一次、心率每秒加一次（[main.cpp:105-111](../firmware/src/main.cpp#L105-L111)、[209](../firmware/src/main.cpp#L209)、[220-222](../firmware/src/main.cpp#L220-L222)）
- 30 秒到 → 取平均 = 基线 `gsr_base`、`hr_base`，回一行 `{"type":"calib","done":1,"gsr_base":…,"hr_base":…}`，`quality` 的 bit2 置 1（[main.cpp:235-241](../firmware/src/main.cpp#L235-L241)、[265](../firmware/src/main.cpp#L265)）
- 之后每个数据包的 `gsr_delta = (当前 − gsr_base) / gsr_base`、`hr_delta = 当前 − hr_base`（[main.cpp:257-260](../firmware/src/main.cpp#L257-L260)）。校准前这两个值恒为 0
- **为什么**：绝对值没有意义——她今天的手汗、电极贴合度和明天不一样，和另一个人更不一样。游戏和分析用的全是"比自己安静时高了多少"（设计决策 6）
- **规矩**：30 秒内静坐、不说话、正常呼吸、不按键；戴上之后先等 1 分钟让电极稳定再校准；重新戴过就重新校准；`acc` 大的那段基线不可信

追问：校准时她偷偷心算了，会发生什么？（基线偏高 → 之后 `gsr_delta` 偏低 → 游戏以为她一直很放松）
