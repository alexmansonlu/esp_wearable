## 1. 项目五阶段框架（会上先讲这个，10 分钟）

> 这是整个项目的**研究叙事**——最后写报告/答辩就按这个讲。

```
S1 目标定义        我们要解决什么问题？成功长什么样？
   ↓
S2 硬件与数据管线   传感器就位、校准流程、数据集采集管线（精确、可复用、随取随用）
   ↓
S3 实验与情绪测量   严谨实验：实时生理数据 → 情绪/状态的映射怎么建立、怎么验证
   ↓
S4 模型设计与验证   基于实验发现建模，验证鲁棒性/公平性/跨人可用性
   ↓
S5 游戏整合        模型接入游戏，实时驱动动态难度与奖励
```

### ⚠️ 排期真相：双轨并行（务必给学生讲清楚）

五阶段是**逻辑顺序**，不是时间顺序——游戏如果等 S4 做完才动工，20 小时根本不够。实际排期是双轨并行，S5 汇合：

```
研究轨:  S1 ──→ S2(硬件/管线) ──→ S3(实验采集) ──→ S4(建模验证) ──┐
                                                                 ├─→ S5 整合
构建轨:        游戏雏形(P3) ──→ 规则式状态判断(P4) ──→ 动态难度(P5) ──┘
                              ↑ 先用简单规则占位，S4 的模型好了再替换
```

**关键设计决策已内置**：游戏先用「规则式状态判断」（阈值 if-else）跑起来——它既是 S4 模型的 baseline 对照组，也保证就算 ML 模型失败，项目仍有完整可交付的成品。这叫**风险分层**，本身就是值得教的工程思维。

## 2.5 教学模式：vibe coding + 代码答辩（会上宣讲的"游戏规则"）

学生**零编程基础**，全项目采用 vibe coding 教学法。每堂课的学习闭环：

```
上课(老师给框架/讲原理) → 课后作业(她指挥 AI 写代码/学概念, git 提交)
     ↑                                        ↓
 答辩不过关回炉 ←── 代码答辩(老师人工 review 提交记录 + 当面提问) ←──┘
```

**三条规则**（当面讲清，写进她的手册 [vibe_coding_入门.md](vibe_coding_入门.md)）：
1. 代码由 AI 写完全合法——但她必须能**解释每一段在干什么、为什么这样写**
2. 答辩弹药来自与 AI 的紧密沟通：手册 §4 有"答辩准备四步法"（让 AI 逐段讲解 → 出预测考题 → 自己作答 → AI 批改）
3. 每次作业以 **git commit** 为交付单位，提交信息她自己写、自己看得懂——老师 review 就看提交记录

老师侧配套：每堂课预留（或课间约）15–20 分钟做上次作业的答辩；提问角度见手册 §4"老师提问的常见角度"。

## 3. S1 目标定义 — 本次会议必须定的决策 ⭐

### D1. 一句话目标（最重要，花最多时间）

引导她把目标说成一句可检验的话。参考模板：

> "做一个节奏游戏：当玩家**紧张/出错/情绪变差**时自动降低难度接住他，当玩家**兴奋/表现好**时给予奖励并提升挑战——并用数据证明这比固定难度**更__**。"

空格处必须选一个可测量的词（这决定 S3 实验测什么）：

| 选项 | 测量方式 | 难度 |
|---|---|---|
| 更好玩（体验） | 赛后主观量表（心流/乐趣评分） | 易 ✅ 推荐 |
| 表现更好（成绩） | accuracy / combo 客观数据 | 易 ✅ 推荐 |
| 更能维持心流状态 | focused 状态时间占比 | 中（依赖模型准确性，有循环论证风险，需讲清） |
| 更减压 | 前后生理基线对比 | 较难 |

**推荐**：主指标选"主观体验 + 客观表现"双指标，心流占比作为探索性指标。

### D2. 「负面情绪→减压」之外，「正面情绪→奖励」怎么做？

她的想法里有"对积极情绪/兴奋给奖励"——这是现有设计没有的新机制，需要定形态：

| 方案 | 说明 | 成本 |
|---|---|---|
| A. 分数奖励 | 检测到兴奋/心流 → 得分倍率 ×1.2 + Fever 特效 | 低 ✅ |
| B. 内容奖励 | 兴奋时解锁华丽段落（tier 3 全开 + 特效） | 中（和难度调整逻辑天然融合）|
| C. 仅视觉/听觉奖励 | 画面变华丽、音效增强，不动数值 | 低（不污染实验数据 ✅）|

**教师注**：方案 A/B 会让"奖励"和"难度"耦合进同一个分数体系，实验分析时要小心混淆变量；C 最干净。可以 C 起步、A 做可选开关。

### D3. 情绪状态集合：五状态够不够？

现有设计：calm / focused / nervous / frustrated / overloaded（ARCHITECTURE §5.2）。
问她：你觉得玩游戏时还有什么状态重要？（常见补充：bored 无聊、excited 兴奋——**excited 正好是 D2 奖励机制需要的**，若定了 D2 建议加入 excited 成六状态）

### D4. 摄像头表情识别：做不做？（她的新想法，需要当场评估）

用笔记本前置摄像头做面部表情/情绪识别，作为生理信号之外的第三通道。

**技术可行性**（如实告知）：
- ✅ 可行：现成方案成熟（MediaPipe Face Mesh / FER 类开源模型 / OpenCV），Python 端跑，不难接入数据管线
- ⚠️ 成本：数据同步（摄像头帧 vs 生理流的时间轴对齐）、光线鲁棒性、算力占用
- ⚠️ 科学性：表情 ≠ 情绪（玩家专注时常面无表情），学界对表情识别情绪的效度本身有争议——反而是个好的批判性思维教学点
- ⚠️ 伦理：录脸涉及隐私，受试者同意书必须单独列明；建议只存表情特征值不存视频

**推荐决策**：定位为 **S3 的可选增强通道**——数据采集时同步录（只存特征值），S4 分析时评估"表情特征对分类准确率有没有增益"，但**游戏实时控制 v1 不依赖它**。这样有科研亮点又不绑架主线。
→ 若采纳：数据管线（S2）要预留 `face_*` 字段与同步机制，第 4 节 S2 决策里体现。

### D5. 范围红线（防止做不完）

和她确认三档范围（GAME_DESIGN.md §7）：必须有 / 加分项 / 明确不做。特别确认：**深度模型（LSTM/Transformer）属于加分项**（原因见 §4-S4），她要有心理预期。

### S4 模型设计与验证（L8 + 课外定案）

**模型复杂度阶梯**（重要教学内容——为什么不能直接上 Transformer）：

```
第0级  规则式阈值 (已设计, ARCHITECTURE §5.2)     ← 游戏 v1 用这个, 也是 baseline
第1级  经典 ML: 逻辑回归 / KNN / 随机森林          ← 数据量: 几百个窗口样本即可 ✅ 我们够
第2级  序列模型: LSTM / GRU / 1D-CNN              ← 需要: 数千以上标注序列 ⚠️ 6-10人很勉强
第3级  Transformer / 预训练生理大模型              ← 需要: 大规模数据集 ❌ 本项目做不到训练,
                                                     但可讨论/引用现成预训练模型作展望
```

| # | 决策 | 要点 |
|---|---|---|
| S4-1 | 主力模型停在哪级 | 推荐：第 1 级为主力交付，第 2 级做对比实验（效果好坏都是发现），第 3 级写进"未来工作" |
| S4-2 | 验证方案 | **GroupKFold 按受试者分组交叉验证**（防止同一人数据泄漏进 train/test 双侧——最常见的造假式高分）|
| S4-3 | 公平性/跨人可用 | 所有特征相对个人基线 + per-subject z-score；报告"留一人验证"（对陌生人准不准）|
| S4-4 | 模型→游戏回接 | 训练好的模型怎么实时跑？（推荐：导出权重→Unity C# 重实现推理 or Python 边车进程走本地 socket）|
| S4-5 | 失败预案 | 模型不比规则好怎么办？→ 报告如实呈现，游戏保留规则式（这也是合法结论）|

## 5. 决策原则（贯穿全项目，会上讲一次）

1. **可测量**：任何目标必须能回答"用什么数据证明"
2. **有 baseline**：任何"更好"都要回答"比什么好"（fixed 对照组、规则式模型）
3. **风险分层**：每个阶段都有"保底可交付"和"冲刺加分"两档
4. **她拍板**：品味类决策（主题/美术/音乐）全部归学生，教师只把关可行性
5. **决策留痕**：每次定案写进决策记录表 → 同步到仓库文档（AI 助手会维护）

## 附录 B. 应急问答（学生可能问的难题）

- **"为什么不直接用 Transformer？现在不都用大模型吗？"** → 模型阶梯图 + 数据量算账：3 分钟 × 3 场 × 8 人 ≈ 72 分钟数据、按 30 秒窗口约 1400 个样本——第 1 级吃得饱，第 3 级要百万级。工程上"能用最简单的方案解决就是最好的方案"。
- **"表情识别不是很成熟了吗？"** → 成熟的是"识别表情"，有争议的是"表情=情绪"；专注的玩家常面无表情。所以它当辅助通道做增益验证，不当主通道。
- **"心率手表就能测，为什么要自己做硬件？"** → 消费级手表不给原始数据/延迟高（秒~分钟级），我们需要 100ms 级实时流；而且自己做才是这门课要学的东西。
