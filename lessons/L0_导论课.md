## 1. 项目五阶段框架（10 分钟）

整个项目的研究叙事，最后写报告 / 答辩按这个讲：

```
S1 目标定义        我们要解决什么问题？成功长什么样？
   ↓
S2 硬件与数据管线   传感器就位、校准流程、数据集采集管线（精确、可复用、随取随用）
   ↓
S3 实验与情绪测量   严谨实验：实时生理数据 → 情绪/状态的映射怎么建立、怎么验证
   ↓
S4 模型设计与验证   基于实验发现建模，验证鲁棒性/公平性/跨人可用性
   ↓
S5 游戏整合        模型接入游戏，实时驱动动态难度与奖励
```

### 排期：双轨并行

五阶段是逻辑顺序，不是时间顺序。研究轨与构建轨并行，S5 汇合：

```
研究轨:  S1 ──→ S2(硬件/管线) ──→ S3(实验采集) ──→ S4(建模验证) ──┐
                                                                 ├─→ S5 整合
构建轨:        游戏雏形(P3) ──→ 规则式状态判断(P4) ──→ 动态难度(P5) ──┘
                              ↑ 先用简单规则占位，S4 的模型好了再替换
```

游戏先用「规则式状态判断」（阈值 if-else）跑起来：它是 S4 模型的 baseline 对照组，也保证 ML 模型失败时项目仍有完整成品（风险分层）。

## 3. 教学模式：vibe coding + 代码答辩

学生零编程基础，全项目采用 vibe coding：她指挥 AI，自己负责需求、验收、决策。

**两步上手**
- L0 作业：用 AI 学懂硬件、和 AI 讨论出游戏提案。不写代码、不用 git，交付为文件
- L1 起：git clone 本仓库，用 AI 读懂仓库、跑第一个脚本、做第一次提交。此后每堂课的闭环：

```
上课(老师给框架/讲原理) → 课后作业(她指挥 AI 写代码/学概念, git 提交)
     ↑                                        ↓
 答辩不过关回炉 ←── 代码答辩(老师人工 review 提交记录 + 当面提问) ←──┘
```

**三条规则**（写在她的手册 [vibe_coding_入门.md](vibe_coding_入门.md)）
1. 代码由 AI 写完全合法，但她必须能解释每一段在干什么、为什么这样写
2. 答辩弹药来自与 AI 的紧密沟通：手册 §4 "答辩准备四步法"（让 AI 逐段讲解 → 出预测考题 → 自己作答 → AI 批改）
3. 从 L1 作业起，每次作业以 git commit 为交付单位，提交信息她自己写、自己看得懂

老师侧：每堂课预留 15–20 分钟做上次作业的答辩；提问角度见手册 §4。

## 4. S1 目标定义 — 本次必须定的决策 ⭐

### D1. 一句话目标

引导她把目标说成一句可检验的话。模板：

> "做一个节奏游戏：当玩家**紧张 / 出错 / 情绪变差**时自动降低难度接住他，当玩家**兴奋 / 表现好**时给予奖励并提升挑战——并用数据证明这比固定难度**更__**。"

空格处选一个可测量的词（决定 S3 实验测什么）：

| 选项 | 测量方式 | 难度 |
|---|---|---|
| 更好玩（体验） | 赛后主观量表（心流 / 乐趣评分） | 易 ✅ 推荐 |
| 表现更好（成绩） | accuracy / combo 客观数据 | 易 ✅ 推荐 |
| 更能维持心流状态 | focused 状态时间占比 | 中（依赖模型准确性，有循环论证风险） |
| 更减压 | 前后生理基线对比 | 较难 |

推荐：主指标"主观体验 + 客观表现"双指标，心流占比作探索性指标。

### D2. 正面情绪 → 奖励，怎么做？

| 方案 | 说明 | 成本 |
|---|---|---|
| A. 分数奖励 | 检测到兴奋 / 心流 → 得分倍率 ×1.2 + Fever 特效 | 低 |
| B. 内容奖励 | 兴奋时解锁华丽段落（tier 3 全开 + 特效） | 中（与难度调整逻辑融合） |
| C. 仅视觉 / 听觉奖励 | 画面变华丽、音效增强，不动数值 | 低（不污染实验数据 ✅） |

注：A / B 会把"奖励"和"难度"耦合进同一分数体系，实验分析时是混淆变量；C 最干净。建议 C 起步、A 做可选开关。

### D3. 情绪状态集合

现有：calm / focused / nervous / frustrated / overloaded（ARCHITECTURE §5.2）。
问她：玩游戏时还有什么状态重要？常见补充：bored、excited。若定了 D2，建议加 excited 成六状态。

### D4. 摄像头表情识别：做不做？

用笔记本前置摄像头做面部表情识别，作为生理信号之外的第三通道。

- ✅ 可行：现成方案成熟（MediaPipe Face Mesh / FER 类开源模型 / OpenCV），Python 端跑
- ⚠️ 成本：摄像头帧与生理流的时间轴对齐、光线鲁棒性、算力占用
- ⚠️ 科学性：表情 ≠ 情绪（专注的玩家常面无表情），表情识别情绪的效度有争议
- ⚠️ 伦理：录脸涉及隐私，同意书单独列明；只存表情特征值不存视频

推荐：定位为 **S3 的可选增强通道**——采集时同步录（只存特征值），S4 分析时评估表情特征对分类准确率的增益；游戏实时控制 v1 不依赖它。若采纳，数据管线预留 `face_*` 字段与同步机制。

### D5. 范围红线

和她确认三档范围（GAME_DESIGN.md §7）：必须有 / 加分项 / 明确不做。特别确认：深度模型属于加分项。投屏模型复杂度阶梯：

```
第0级  规则式阈值 (已设计, ARCHITECTURE §5.2)     ← 游戏 v1 用这个, 也是 baseline
第1级  经典 ML: 逻辑回归 / KNN / 随机森林          ← 几百个窗口样本即可 ✅ 我们够
第2级  序列模型: LSTM / GRU / 1D-CNN              ← 需数千以上标注序列 ⚠️ 6–10 人很勉强
第3级  Transformer / 预训练生理大模型              ← 需大规模数据集 ❌ 本项目不训练, 只作展望
```

数据量账：3 分钟 × 3 场 × 8 人 ≈ 72 分钟，按 30 秒窗口约 1400 个样本——第 1 级够用，第 3 级要百万级。

## 5. 游戏设计开放讨论 G1–G5（只讨论、不定案）⭐

本节今天不拍板。每题 1–2 分钟：讲清问题是什么、为什么重要、有哪几种可能。课后她与 AI 逐题讨论，L1 带一页提案来。

### 总原则：先简单，先 demo，不上完整机制

```
❌ 一上来做"4轨 + 长按 + 特效 + 生理难度 + 奖励"的完整游戏
✅ 一串各自 20–60 分钟就能做出来的小 demo，每个只验证一件事，做完一个再要下一个
```

demo 阶梯（对应 TODO.md P3）：

| # | Demo | 只验证一件事 | 验收标准 |
|---|---|---|---|
| A | 节拍器点击 | **在正确时刻按键并立刻得到反馈**——没有音符、没有轨道，只有滴答声 + 一个键 | 每次按键显示早 / 晚了多少 ms；Perfect / Good / Miss 判得对 |
| B | 单轨下落 | 音符从上往下落，落到线上按 | 音符与滴答声对齐；刻意早按 / 晚按得到不同判定 |
| C | 4 轨 + 谱面文件 | 读 chartgen 生成的谱面 JSON | 一首 60 秒的歌能完整打完，有分数和连击 |
| D | 假情绪旋钮 | 用键盘 1–5 模拟情绪状态，改变**一个**难度杠杆 | 按 1 音符变少 / 慢，按 5 变多 / 快；画面上已有的音符不跳位 |
| E | 接真传感器 | 把 D 的旋钮换成 ESP32 送来的状态 | P4 / P5 阶段 |

Demo A 是最重要的最小机制：**时间判定 + 即时反馈**。它做错（音画不同步），后面全白搭。Demo A–D 都不需要传感器。

### G1. 参考哪些游戏？借什么？

课后各看 30 秒–3 分钟视频，写下"我想借它的哪一点"：

| 游戏 | 按键数 | 值得借的点 |
|---|---|---|
| osu!mania / DJMAX / Deemo | 4+ | 标准下落式布局，现有设计的默认形态 |
| Rhythm Doctor（节奏医生） | **1** | 一个键也能做出深度；判定反馈极清楚（"早了 / 晚了"） |
| A Dance of Fire and Ice（冰与火之舞） | 1–2 | 极简输入；失败后立即重来、不羞辱玩家 |
| Muse Dash | 2 | 上下两键、宽容度高，"不让人挫败"的范本 |
| 太鼓达人 | 2 | 两种音符、节奏骨架清晰 |
| Tetris Effect | — | 画面 / 音乐随玩家表现变化；Zone 机制 = 奖励形态参考 |
| Nevermind（2015） | — | **真的用心率传感器调难度的商业游戏**，必看 |
| Left 4 Dead 的 AI Director | — | 隐藏式动态难度（玩家不知道被调）→ 对应 G4 "要不要让玩家看见" |

问她：你玩过什么节奏游戏？最喜欢哪一个的什么感觉？

### G2. 最先做通的"一个"核心机制是什么？

把所有东西都拿掉之后，剩下的最小可玩单位是什么？

- 参考答案：**在正确的时刻按下一个键，并立刻知道自己按得准不准**（= Demo A）
- 追问：只有这一个机制、没有音符没有画面，好玩吗？为什么音游要看得见音符往下掉？（→ lookahead：让玩家能提前准备，而不是纯靠反应）
- 她带回：**你的 Demo A 长什么样？屏幕上有什么、按什么键、显示什么反馈？**（手画草图拍照）

### G3. 几个按键？

| 方案 | 优点 | 代价 | 对"情绪→难度"的意义 |
|---|---|---|---|
| 1 键 | 最容易上手（受试者不必是玩家）；demo 最快 | 难度只能靠密度 / 速度 | 杠杆少但干净，实验变量少 |
| 2 键（左 / 右） | 仍易上手，多了"选择"维度 | 谱面要分左右 | 密度 + 交错 |
| 4 键（D F J K） | 标准音游、难度上限高、现有设计按这个写 | 非玩家受试者前几分钟手忙脚乱 → 基线就是紧张的 | 三维杠杆全可用 |

提醒：受试者是 6–10 个普通人，不是音游玩家。"她自己觉得好玩"和"受试者能在 3 分钟内进入状态"是两个标准。可行折中：demo 用 1 键、正式版 2 或 4 键。

### G4. 情绪模型怎么影响难度？动哪个杠杆、怎么动？

可动的杠杆：

| 杠杆 | 玩家感受 | 实现难度 | 副作用 / 注意 |
|---|---|---|---|
| 歌曲 BPM / 播放速度 | 整首歌变快慢 | 中 | 变速会变调；谱面时间轴要同步缩放；同一首歌各场不一致 → 实验难比较 ⚠️ 不建议首选 |
| 音符下落速度 note_speed | 反应时间的紧迫感 | 低 | 只能影响新出现的音符 |
| 判定窗口宽度（Perfect ±40ms → ±60ms） | 宽容度：同样的手更容易 Perfect | 低 | 改变了 accuracy 的意义，分析时必须记录当时的窗口宽度 |
| 音符密度（tier 过滤） | 手忙程度 | 低（谱面已带 tier） | 最自然：节奏骨架不变，只增减装饰音 ✅ 推荐 demo 首选 |
| 型态复杂度（双押 / 交错） | 脑子转不过来 | 中 | 需要谱面标注 pattern |

"怎么动"的四个问题（每个都带答案回来）：

1. **几档**？连续数值（0.7×–1.4×）还是三档（轻松 / 标准 / 紧张）？三档好解释、好测试、好写报告；连续更平滑
2. **多久调一次**？每小节？每 10 秒？状态一变就调？太频繁玩家会晕，太慢等于没调（现有设计：10 秒冷却 + 小节边界，ARCHITECTURE §5.4）
3. **一次调多少**？一步一小格还是一步到位？
4. **玩家看不看得见**？完全无感 / 一个小图标 / 明确说"我帮你放慢了"。影响体验也影响实验

简化建议：Demo D 只动一个杠杆、只分三档、只在小节边界调。

### G5. 奖励与正向反馈：怎么让玩家不因失误而沮丧？

设计品味 + 心理学，Nick 可参与。两个子问题：

**(a) 检测到正面情绪 / 兴奋时怎么奖励？**（与 D2 联动：D2 定形态，这里定"感觉"）
- 分数倍率？画面变华丽（Fever）？解锁更炫的段落？音乐叠一层？
- 追问：奖励会不会反过来让人紧张（"我要保持住！"）？

**(b) 失误时怎么反馈，才能让玩家保持乐观、继续玩？**
先问她：你玩游戏时什么时候会想放弃？什么设计会让你失败了还想再来一次？讨论素材：

| 传统做法 | 更温柔的替代 |
|---|---|
| 大红字 MISS + 难听音效 | 小字 EARLY / LATE（告诉方向而不是宣判失败），音效中性 |
| 连击归零 | 连击"护盾"：情绪低落时第一次 miss 不断连；或只显示最高连击 |
| 血条见底 → 歌曲中断 | 不设失败条件（实验也需要完整 3 分钟数据） |
| 结算只看分数 | 结算突出"你的最佳段落""比上次进步的地方""这段你紧张了，游戏帮你放慢了" |
| 悄悄降难度 | 措辞：不是"难度下降"，而是"节奏放松一下 🎵"或呼吸引导 |
| 沉默 | 找回节奏时一句"回来了！"——恢复比完美更值得奖励 |

- 她带回：从上表挑 2–3 条，或提自己的，并说明为什么
- 注：这些反馈本身会改变玩家情绪，是 S3 实验的混淆变量。v1 先做最少的（EARLY / LATE + 不设失败），其余做成可开关的体验层，实验时三组一致

AI 提示词模板：

```
「我是零基础学生，在做一个"读情绪的节奏游戏"。请先读我上传的 GAME_DESIGN.md 和

 以及对"普通人受试者"的影响，不要替我决定。我选完后帮我把理由整理成 4 行提案。」
```

L1 看的是：理由是不是她自己的、有没有听懂 AI 的备选方案、有没有主动问"为什么"、有没有把复杂想法拆小。

## 6. 决策原则（贯穿全项目）

1. **可测量**：任何目标必须能回答"用什么数据证明"
2. **有 baseline**：任何"更好"都要回答"比什么好"（fixed 对照组、规则式模型）
3. **风险分层**：每个阶段都有"保底可交付"和"冲刺加分"两档
4. **她拍板**：品味类决策（主题 / 美术 / 音乐）全部归学生，教师只把关可行性
5. **决策留痕**：每次定案写进会议纪要 → 同步到仓库文档
