# Vibe Coding 入门手册（学生版）

> 这份手册是给你的：本项目所有代码都会由你**指挥 AI 写出来**（vibe coding），
> 但每堂课后老师会对代码做人工 review 并向你提问——**你必须能解释你交出的每一段代码在干什么**。
> AI 是你的手，脑子必须是你自己的。

---

## 1. 什么是 vibe coding？

用自然语言（中文就行）告诉 AI 你想要什么，AI 写代码，你负责**验收、提问、决策**。你的角色不是打字员，而是：

| 你的角色 | 具体做什么 |
|---|---|
| 产品经理 | 说清楚"我要什么"：目标、输入输出、边界情况 |
| 质检员 | 跑一跑、试着弄坏它、把报错原文丢回给 AI |
| 学习者 | 每段代码都追问"这在干嘛、为什么这样写"，直到能自己讲出来 |
| 决策者 | AI 给方案 A/B/C 时，**由你来选**，并知道为什么 |

一句话：**vibe coding ≠ 不用懂代码，而是换了一种懂代码的方式**——从"会写"变成"会读、会问、会判断"。

## 2. 装机清单（L0 课上一起装，装不完课后远程协助）

1. **VSCode**：https://code.visualstudio.com/ （代码编辑器，免费）
2. **AI 编程助手**（老师会帮你选定其一并处理账号）：
   - 推荐：**Claude Code**（VSCode 扩展市场搜 "Claude Code" 安装，或官方文档 https://code.claude.com/docs）——本项目的文档记忆（CLAUDE.md）就是为它准备的，AI 打开项目就知道全部背景
   - 备选：Cursor（https://cursor.com，内置 AI 的编辑器）
3. **验收标准**：打开本项目文件夹 → 对 AI 说"请读一下这个项目的 CLAUDE.md，用三句话告诉我这个项目在做什么"→ 它答对了，装机完成 ✅

## 3. 五个基本功（每次对话都用得上）

1. **给上下文**：别说"帮我写个读传感器的代码"，要说"在本项目 firmware 里，我想让 GSR 的采样频率从 50Hz 改成 100Hz，相关配置在哪、要改什么？"——**项目文件夹要先打开**，AI 能看到全部文件。
2. **小步走**：一次只要一个小功能，跑通了再要下一个。一口气要十个功能 = 十个 bug 一起来。
3. **必须要解释**：每次 AI 写完，追问一句「**逐段解释这些代码在干什么，用我能听懂的比喻**」。这是你答辩的弹药，也是你真正学到东西的时刻。
4. **报错原文贴回去**：程序报错时，把红字**完整**复制给 AI（包括文件名和行号），不要自己转述"它坏了"。
5. **让 AI 出选择题，别让它替你决定**：设计类问题说"给我 2–3 个方案，各自优缺点，你推荐哪个、为什么"——最后**你**拍板。

## 4. 代码答辩制度（本课程的核心规则）

### 规则

- 每堂课的课后作业用 vibe coding 完成
- 下堂课（或约定时间）老师人工 review 你的代码，并**当面提问**
- 答不上"这段代码在干嘛/为什么这么写"= 这次作业不过关，回去和 AI 补课再来
- **允许**：代码是 AI 写的（这正是课程设计）；**不允许**：交出自己讲不明白的代码

### 答辩准备四步法（每次交作业前照做）

把下面的提示词依次发给你的 AI：

```
第1步 「把这次写的代码逐文件、逐段给我讲解，假设我没有编程基础，多用比喻。」
第2步 「如果一位懂技术的老师要考我这份代码，最可能问哪 8 个问题？列出来。」
第3步 （自己先口头回答这 8 个问题，答不出的标记下来）
第4步 「我对第 X 题的回答是：……。请批改：哪里对、哪里错、怎么补。」
```

> 小技巧：答辩时可以带笔记，但**不能现场问 AI**——所以第 3 步别偷懒。

### 老师提问的常见角度（提前有数）

- "这个文件/函数删掉会发生什么？"
- "这个数字（比如 50Hz、120ms）为什么是这个值，改大改小会怎样？"
- "数据从传感器到画面上，经过了哪几站？"
- "如果 XX 坏了/断了，程序会怎么表现？"

## 5. Git 基本功（代码的"存档系统"，必学）

### 为什么必须学

- 本项目所有代码和文档都放在一个 **git 仓库**里，老师 review 你的作业就是看你的**提交记录（commit）**
- 没有 git：改坏了回不去、换电脑东西带不走、老师看不到你每次改了什么
- 好消息：git 命令可以让 AI 帮你执行，但**每个动作的含义你必须懂**（这也是答辩内容）

### 要懂的 5 个概念（让 AI 用比喻给你讲透）

```
「用游戏存档打比方，给零基础的我解释 git 的这 5 个概念：
 仓库(repository)、提交(commit)、提交信息(commit message)、
 历史(log)、推送(push)。每讲一个举一个本项目里的实际例子。」
```

### 每次作业的标准动作（做完作业必执行）

```
1. 让 AI：「检查一下我这次改了哪些文件（git status / git diff），逐个告诉我改动是什么」
2. 你确认这些改动都是你知道并想要的（有不认识的改动就问！）
3. 让 AI：「帮我提交，提交信息用中文写清楚这次做了什么」
4. 让 AI：「推送到远端」（老师就能看到了）
```

⚠️ 规矩：**提交信息（commit message）必须你自己看得懂**——答辩时老师会指着某次 commit 问"这次你干了什么"。

### 安装

- 下载 git：https://git-scm.com/download/win （一路默认下一步即可）
- 装完在 VSCode 里对 AI 说：「确认我的 git 装好了，并帮我设置用户名和邮箱」

## 6. 你的第一个任务：用 AI 学懂全部硬件（L0 → L1 作业）⭐

L1（9/11 线下课）我们要一起组装硬件。**开场会有 10 分钟快问快答**，你需要提前学懂清单上每一样东西。

### 做法

打开项目文件夹，让 AI 读 `HARDWARE.md`，然后**每样硬件走一轮**这个模板：

```
「我是零基础学生。请根据本项目的 HARDWARE.md，用初中生能懂的方式给我讲解【ESP32】：
 1. 它是什么、在我们项目里负责什么？
 2. 它的工作原理，用一个生活中的比喻来说明
 3. 它输出的数据长什么样、这些数据后面怎么被游戏用到？
 讲完后出 3 道题考我。」
```

【】里依次换成清单上的 6 样：
1. ESP32 开发板
2. Grove GSR 皮肤电传感器
3. PulseSensor 光电脉搏传感器
4. AD8232 心电模块
5. MPU6050 六轴传感器
6. 裸 MAX30100（选配件）

### 交付物（L1 带来）

每样硬件写 **3–5 行自己话的笔记**（不许复制粘贴 AI 原文——写不出自己话 = 还没懂，回去再问）。格式：

```
【GSR 皮肤电】
它测的是：____
原理一句话：____
在游戏里的用途：____
我还没搞懂的一个问题：____   ← 这条最有价值，课上优先解答
```

### 快问快答会考的方向（透题了，好好准备）

- 为什么心率传感器有三个？各自什么定位？
- GSR 为什么不能接 5V？
- MPU6050 明明不测情绪，为什么它很重要？
- "皮肤电导上升"通常意味着人怎么了？

## 8. 红线与好习惯

- ⚠️ **不要盲目接受代码**：AI 会犯错、会一本正经地胡说。跑之前先让它解释，跑之后自己验证行为对不对。
- ⚠️ **保留对话记录**：答辩时"我当时是这样问的、AI 是这样解释的"是合法引用；删光记录 = 重学一遍。
- ⚠️ **隐私**：实验受试者的数据（心率、皮电、更别说人脸）不要粘贴到与项目无关的在线工具里。
- ✅ 每次学到一个新概念，用自己的话在笔记里写一行——期末这份笔记就是你的答辩武器库。
- ✅ 卡住超过 20 分钟就换个问法，或截图/复制现象给 AI；再不行，记下来带到课上问老师。
