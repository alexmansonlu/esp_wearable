## 0. 需要与 Nick 先对齐的事项（一页摘要，可直接发 Nick）

建议约一次 **30–45 分钟线上对齐**，时点：**L3（9/19）前**——因为 S2-4 数据格式在 L3 定，而字段设计取决于 ground truth 方案。E1（10/17 前后）前再对一次 S3 细节。

| # | 要对齐什么 | 为什么要先对 | 建议时点 |
|---|---|---|---|
| S2-2 | 校准段做什么：闭眼？呼吸引导？静坐时长 30s 还是 60s | 基线质量决定后面所有"相对变化量"的意义；呼吸引导本身会压低唤醒，可能让基线"太平静" | L3 前 |
| S2-5 | 受试者数据管理：编号、去识别化、存储位置、谁能访问、保留多久 | 伦理与同意书要写清；若 D4 摄像头采纳，人脸特征值属敏感数据 | L3 前 |
| S3-1 | Ground truth 从哪来：赛后量表 / 事件标记按钮 / 刻意"地狱段落"诱发挫折 | "诱发挫折"有伦理与体验成本，Nick 要点头；量表选哪份（心流量表？PANAS？）Nick 定 | L3 前（定字段）；E1 定细节 |
| S3-2 | adaptive / fixed / sham 三组 + 顺序平衡 | 已写进架构，但 sham 的"随机小幅调整"怎么设计才像真的、又不伤体验，需要 Nick 判断 | E1 前 |
| S3-3 | 受试者人数、招谁、同意书内容 | 6–10 人是底线；同意书若含摄像头需单独条款 | E1 前 |
| S3-4 | 每场 SOP 与分工 | 谁主持、谁记录、谁盯信号质量；N2 实测调参场就是排练 | E1 前 |
| S3-5 | "严谨"的操作定义 | 同一时段采集、温度记录、咖啡因/运动排除——Nick 补心理生理学角度的排除标准 | E1 前 |
| S5-HUD | 游玩中显不显示生理数据 | 观察者效应：看见自己心率可能更紧张——可做成实验变量（显示/隐藏两组），要 Nick 判断值不值得加一个因子 | L5 前 |
| S4-3（可选） | 跨人公平性怎么报告 | Nick 可从个体差异角度给"留一人验证"的解读建议 | L8 前 |

> 对齐结论回填本文件附录 A，并同步 ARCHITECTURE §7.3 待确认清单。

## 3. S4 模型设计与验证（L8 + 课外定案）

**模型复杂度阶梯**（重要教学内容——为什么不能直接上 Transformer；L0 D5 会用到这张图）：

```
第0级  规则式阈值 (已设计, ARCHITECTURE §5.2)     ← 游戏 v1 用这个, 也是 baseline
第1级  经典 ML: 逻辑回归 / KNN / 随机森林          ← 数据量: 几百个窗口样本即可 ✅ 我们够
第2级  序列模型: LSTM / GRU / 1D-CNN              ← 需要: 数千以上标注序列 ⚠️ 6-10人很勉强
第3级  Transformer / 预训练生理大模型              ← 需要: 大规模数据集 ❌ 本项目做不到训练,
                                                     但可讨论/引用现成预训练模型作展望
```

| # | 决策 | 要点 | 先由谁谈 |
|---|---|---|---|
| S4-1 | 主力模型停在哪级 | 推荐：第 1 级为主力交付，第 2 级做对比实验（效果好坏都是发现），第 3 级写进"未来工作" | 🔒 教师定 → 📣（L0 D5 已给心理预期） |
| S4-2 | 验证方案 | **GroupKFold 按受试者分组交叉验证**（防止同一人数据泄漏进 train/test 双侧——最常见的造假式高分） | 🔒 教师定 → 📣 L8 教 |
| S4-3 | 公平性/跨人可用 | 所有特征相对个人基线 + per-subject z-score；报告"留一人验证"（对陌生人准不准） | 🔒 教师定；🤝 Nick 可选给解读建议 |
| S4-4 | 模型→游戏回接 | 训练好的模型怎么实时跑？（推荐：导出权重→Unity C# 重实现推理 or Python 边车进程走本地 socket） | 🔒 教师定 → 📣 |
| S4-5 | 失败预案 | 模型不比规则好怎么办？→ 报告如实呈现，游戏保留规则式（这也是合法结论） | 🔒 教师定 → 📣（提前讲，免得她把"模型没赢"当失败） |
