# GAME_DESIGN.md — 游戏设计文档

> 用途：① 导论课与客户讨论"游戏应该怎么设计"的教学材料；② 开发期间的设计基准。
> 标 🗣️ 的小节是**留给客户决定的开放问题**，导论课上一起讨论定案。
> 版本：v0.1（导论课后更新为 v1.0）

## 1. 一句话定位

> 一个**会读你情绪的节奏游戏**：你越紧张它越温柔，你越从容它越刁钻——目标是把玩家一直留在"心流"里。

这也是整个项目的研究命题：动态难度（DDA, Dynamic Difficulty Adjustment）+ 生理信号，能否比固定难度带来更好的体验与表现。

## 2. 设计理论快速课（导论课讲这个）

### 2.1 心流通道（Csikszentmihalyi）

```
 难度 ↑
      │        焦虑区 (anxiety)
      │      ╱╱╱╱╱╱╱╱╱
      │    ╱╱ 心流通道 ╱╱      ← 我们的游戏要把玩家"锁"在这条斜带里
      │  ╱╱╱╱╱╱╱╱╱
      │ 无聊区 (boredom)
      └──────────────────→ 技能 ↑
```

传统游戏用固定难度曲线赌"平均玩家"；我们用**生理信号实时探测**玩家在哪个区，然后把难度推回通道内——这是本项目相对普通音游的核心创新。

### 2.2 MDA 框架（Mechanics → Dynamics → Aesthetics）

| 层 | 我们的对应 |
|---|---|
| Mechanics 规则 | 4 轨下落音符、判定窗口、连击、生理难度调整 |
| Dynamics 玩法动态 | 玩家追求 FC（全连）、紧张时被游戏"接住"、放松时被挑衅 |
| Aesthetics 体验 | 挑战（Challenge）+ 感官愉悦（Sensation）+ 自我发现（"原来我紧张时是这样的"） |

设计任何功能时先问：它最终服务哪种体验？

### 2.3 节奏游戏的手感三要素

1. **判定要诚实**：玩家按准了就必须给 Perfect——音画同步误差是音游的死罪（所以我们用 `dspTime` 音频时钟，不用帧时钟）
2. **反馈要即时且分层**：视觉（判定字/粒子）+ 听觉（击打音）+ 数字（连击跳动）在 50ms 内全部到位
3. **失败要可理解**：Miss 时玩家要能知道自己是早了还是晚了（显示 EARLY/LATE）

## 3. 核心玩法定义

### 3.1 基本规则

| 项 | 设定 | 说明 |
|---|---|---|
| 轨道数 | 4 | 按键 D / F / J / K（双手各两指，标准下落式布局） |
| 音符类型 v1 | Tap（单点） | 先只做单点，手感打磨好再说 |
| 音符类型 v2（可选） | Hold（长按） | 时间富余再加 |
| 判定窗口 | Perfect ±40ms / Great ±80ms / Good ±120ms / Miss | 行业常规值，pilot 后可调 |
| 一首时长 | 60–180 秒 | 实验每场 3 分钟，配合采集设计 |

### 3.2 计分与连击

```
Perfect = 100 分   Great = 70 分   Good = 40 分   Miss = 0 分 + 断连
连击加成：分数 × (1 + combo/100)，上限 ×2
Accuracy = 加权命中率（Perfect=1, Great=0.7, Good=0.4）
结算评级：S ≥ 95% / A ≥ 90% / B ≥ 80% / C ≥ 70% / D 其他
```

### 3.3 难度三维（生理自适应的操作对象）

| 维度 | 范围 | 玩家感受 |
|---|---|---|
| note_speed 下落速度 | 0.8×–1.6× | 反应时间压力 |
| note_density 音符密度 | 0.7×–1.4×（tier 过滤实现） | 手忙程度 |
| pattern_complexity 型态复杂度 | 1–5 | 交错、双押、切分出现与否 |

生理状态 → 难度动作的映射规则见 [../ARCHITECTURE.md](../ARCHITECTURE.md) §5.4。核心原则：**focused（心流）状态时难度一动不动**。

### 3.4 谱面与 tier 分级（密度调整的实现基础）

每个音符带 `tier` 属性（1=骨架 / 2=正拍 / 3=装饰）：

```
tier 1：小节强拍（每小节第 1 拍）——任何难度下都保留，节奏骨架
tier 2：其余正拍——中等以上密度保留
tier 3：反拍/切分/onset 装饰音——高密度才出现
```

`note_density` 调整 = 改变保留的 tier 阈值 → 音符变少但**节奏骨架不塌**，玩家不会觉得"歌变了"。谱面由 `tools/chartgen.py` 从音乐自动生成初稿，再人工微调。

## 4. 画面与流程

### 4.1 场景流程

```
00_Boot(设备连接检查) → 01_Calibration(60秒静息校准,呼吸引导动画)
      → 02_Gameplay(游玩) → 03_Result(结算+生理回放曲线) → 回选曲/再来一次
```

结算画面的**生理回放**是本作特色：HR/GSR 曲线 + 状态色带 + 难度阶梯叠在一起，玩家能看到"这一段我紧张了、游戏帮我降了难度"。

### 4.2 游玩画面布局（HUD 草图）

```
┌─────────────────────────────────────────────┐
│ SCORE 154,320      ♥ 78  ~41ms   GSR ▂▃▅   │  ← 生理 HUD（可开关）
│ COMBO 42           状态: ● focused          │
│                                             │
│    │ D │ F │ J │ K │                        │
│    │   │ ▆ │   │   │      ← 音符下落        │
│    │ ▆ │   │   │ ▆ │                        │
│    │   │   │ ▆ │   │                        │
│  ══╪═══╪═══╪═══╪═══╪══    ← 判定线           │
│    │   │   │   │   │      PERFECT! (EARLY)  │
│  ▓▓▓▓▓▓▓▓░░░░░░░░░░░      ← 歌曲进度         │
└─────────────────────────────────────────────┘
```

🗣️ **待讨论**：生理数据实时显示会不会反过来让玩家更紧张（观察者效应）？可做成实验变量（显示/隐藏两组）——这本身就是个好的心理学讨论点，可请 Nick 参与设计。

### 4.3 状态的视觉语言

| 状态 | 颜色 | 环境反馈（微妙，不干扰游玩） |
|---|---|---|
| calm | 蓝 | 背景平静 |
| focused | 绿 | 背景微微流光 |
| nervous | 黄 | 判定线轻微脉动 |
| frustrated | 橙 | 背景降饱和、节拍提示增强 |
| overloaded | 红 | 画面边缘柔光呼吸提示（暗示深呼吸） |

原则：**环境反馈不能惩罚玩家**——已经手忙脚乱时闪瞎眼是反设计。

## 5. 音乐选择

### 选曲标准（technical）

- BPM 100–140（太慢没压力、太快超出难度调整空间）
- 节拍清晰（鼓点明显的电子乐/流行乐最好，自由节奏的古典/氛围乐不行）
- 60–180 秒或可裁剪
- **版权可用**：CC0 / CC-BY 素材站（Free Music Archive、incompetech、魔王魂）或客户自己的原创

🗣️ **待讨论**：客户想玩什么歌？喜欢什么风格？（选她喜欢的歌，测试动力完全不同）

## 6. 🗣️ 导论课讨论清单（逐项过，记录决定）

1. **主题/世界观**：纯抽象轨道？还是有主题包装（太空/海洋/像素复古…）？
2. **美术风格**：极简几何（开发最快）/ 像素风 / 霓虹赛博？→ 决定 Art 工作量
3. **音乐**：用哪几首？来源与版权？
4. **生理 HUD**：游玩中显示还是隐藏？（见 4.2 讨论点）
5. **键位**：DFJK 可以吗？她习惯别的布局吗？
6. **难度反馈透明度**：难度变化时要不要提示玩家（"难度↓"图标）？还是完全无感？（提示 = 玩家知道被照顾，可能影响实验）
7. **失败条件**：要不要血条/歌曲中断？（建议：**不要**，实验需要完整 3 分钟数据）
8. **她自己最想加的一个功能**？（所有权感 = 学习动力）

## 7. 范围控制（防止做不完）

**必须有（P3–P5）**：4 轨 tap、判定、连击计分、谱面加载、生理 HUD、动态难度、数据记录
**加分项**：Hold 音符、粒子特效、多首歌选曲界面、生理回放动画
**明确不做**：多人、手机版、自制谱面编辑器 UI、剧情

> 判断标准：砍掉它会影响"生理自适应难度"这个核心命题吗？不影响就是加分项。
